# Contributing

Use Python 3.11 or newer and read AGENTS.md and SECURITY.md first. This is a
preliminary disk-writing application: safety defects take priority over features.

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -e '.[dev]'
.venv/bin/python -m pytest
.venv/bin/ruff check .
.venv/bin/ruff format --check .
.venv/bin/bandit -r src
.venv/bin/mypy src --ignore-missing-imports
.venv/bin/python -m compileall -q src tests
.venv/bin/python -m build
mkdir -p build
.venv/bin/python scripts/audit_requirements.py > build/audit-requirements.txt
.venv/bin/pip-audit --strict --no-deps --disable-pip -r build/audit-requirements.txt
```

Keep changes focused. Include regression tests and both English and Spanish
user-facing wording. Explain behavior before and after, failure handling and the
limits of the tests in your pull request. Device tests must use injected backends
or disposable regular files. Never direct a test at a real disk. Loop-device tests
need explicit separate authorization and must not become a default CI step.

Do not include Windows files, proprietary drivers, private logs or credentials.
Synthetic fixtures should be generated by tests. Reference upstream technical
documentation for format changes. Do not weaken confirmation, disk identity,
permissions, checksum checks or error propagation to obtain a passing test.

Before changes affecting release safety, request an independent review focused on
wrong-device writes, hotplug races, unexpected privilege use and false success.
Hardware claims need recorded hardware evidence, separate from software tests.

## Español

Usa Python 3.11 o posterior y lee AGENTS.md y SECURITY.md. Prioriza los defectos
que puedan causar pérdida de datos. Aporta pruebas de regresión, mensajes en
ambos idiomas y una descripción de los límites de la validación. Ninguna prueba
puede escribir en discos reales. Los fixtures deben ser sintéticos y no contener
archivos de Windows, drivers propietarios, registros privados o credenciales.

No relajes comprobaciones para obtener resultados favorables. Los cambios en
escritura de discos necesitan revisión independiente de identidad, permisos,
condiciones de carrera y mensajes de éxito. Una afirmación de compatibilidad en
hardware requiere evidencia física propia.
